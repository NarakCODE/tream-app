# Resource revisions and permanent issue identifiers

**Status:** Accepted for the authorized M07–M09 implementation.

Issues, cycles, comments, labels and issue templates expose a persisted positive `revision`. Mutations of an existing resource require `expectedRevision` in the JSON body, compare it after current authorization under the owning transaction lock, and return 409 on a mismatch. The JSON revision is the canonical concurrency contract; HTTP ETag/If-Match is not an additional requirement. This avoids two competing precondition mechanisms for commands with JSON bodies, including DELETE. Idempotent replay checks current authorization before returning the original response and does not reject the original expected revision merely because that command already committed.

Database triggers advance revisions for existing writers that omit the new column, accept an explicit increment of exactly one, and reject regression or arbitrary jumps. Operational scheduler error metadata does not advance a cycle's business revision. Resource revisions are separate from event aggregate revisions: one transaction can contain multiple facts for an aggregate and uses one reserved event revision, while each changed resource has its own persisted revision.

Issue numbers are allocated under the team lock inside the creation or transfer transaction. PostgreSQL owns current identifier projection and permanent aliases: the old identifier remains reserved after transfer, archive and trash, exactly one alias is current, and aliases cannot be reassigned or hard-deleted. Transfers retain the internal issue ID and allocate a fresh destination number; failure rolls back the counter, aliases, linked planning changes, labels and facts together.

Workspace rows serialize graph and scope changes; issue hierarchy and dependency cycles are rejected at the database boundary as well as in commands. Private team access is required for a visible issue and all its parent ancestors, plus every team of an assigned project. This prevents a public child from exposing a private parent reference. Separate Issues, Cycles and Collaboration modules follow the current scaffolds and the M05/M06 documented privacy policy; the older combined-module and hidden-resource-403 details of ADR 0001 are superseded, while the separation of CRM Tasks from product Issues remains unchanged.
