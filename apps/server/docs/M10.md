# M10 — Private files and attachments

M10 extends issues, projects and collaboration with private uploads and typed attachments. Documents join this workflow in M11. The frontend remains a separate milestone.

## Local development

The default `FILES_STORAGE_DRIVER=filesystem` stores opaque objects under `apps/server/.local/files` when the server starts from its package directory. The directory is ignored by Git and is never served by a static route. Set `FILES_LOCAL_ROOT` to an absolute private directory to remove any dependence on the process working directory.

The default `FILES_SCANNER_DRIVER=development` detects the EICAR test pattern and runs the content policy; it is **not a full antivirus scanner**. To exercise real ClamAV locally:

```sh
cd apps/server
docker compose --profile scanning up -d clamav
```

After the scanner is healthy, set `FILES_SCANNER_DRIVER=clamav`, `FILES_CLAMAV_HOST=localhost`, and `FILES_CLAMAV_PORT=3310`, then restart the API. The optional container uses the official ClamAV feature-release image and a persistent signature volume. Keep the scanner TCP listener on the private network; see the [official ClamAV socket documentation](https://docs.clamav.net/manual/Usage/Scanning.html) and [Docker instructions](https://docs.clamav.net/manual/Installing/Docker.html).

## Deployment configuration

Production startup requires S3-compatible storage, a ClamAV daemon and an explicit independent `FILES_SIGNING_SECRET`. Configure `FILES_BUCKET`, `FILES_REGION`, and optionally `FILES_ENDPOINT` for a compatible HTTPS service. Optional access/secret keys must be supplied together; otherwise the AWS credential provider chain supplies deployment credentials. Provision a private bucket and least-privilege object access separately. No cloud infrastructure is created by API startup.

JSON requests keep their 1 MiB parser limit. Binary uploads use `Content-Type: application/octet-stream` and are bounded by `FILES_MAX_FILE_BYTES` before reaching the controller. Default per-file size is 25 MiB and workspace quota is 1 GiB. Pending uploads, quarantined files and trash continue reserving their bytes until storage removal succeeds.

## Authorization and lifecycle

An upload intent names exactly one issue, project or comment. Every operation verifies workspace membership and inherited target visibility, including private issue ancestors and project team dependencies. An additional attachment never widens access: the file’s immutable originating target remains a prerequisite for metadata, lists and download, even if another link names a public resource. Upload grants and download grants are short-lived and bound to the authenticated session and attachment. Downloading always checks current target visibility and lifecycle again; an old URL does not preserve revoked access.

File names are normalized for safe attachment download headers. Actual bytes must match declared size and SHA-256 and an allowlisted content type. HTML, SVG, archives and executable content are rejected. Finalization gates download on successful scanning. A scanner failure never makes an upload ready. The PDF policy also rejects compressed object streams and active/embedded dictionaries, because its conservative byte-level checks do not parse hidden PDF objects.

Mutations use the existing UUID idempotency contract and persisted revisions. Binary writes use immutable object keys and checksum-based replay rather than a JSON command key. Metadata does not expose storage keys or grant signing secrets. File facts and attachment facts contain only resource IDs and stable quarantine reasons.

The uploader or a visible workspace administrator controls file lifecycle with write access to the immutable originating target. Secondary links cannot prevent the uploader from deleting their own content; detaching a secondary link still requires permission on that target.

Deletion retains file and attachment placeholders. Restore is available before a cleanup job begins physical purge. Abandoned intents and deleted files enter durable leased cleanup jobs. The worker honors `BACKGROUND_WORKERS_ENABLED`; disable timers in tests and run the same sweep explicitly. Object deletion can be retried after storage or database failures, and quota is released only after confirmed deletion. `FILES_CLEANUP_MAX_ATTEMPTS` saturates the attempt counter rather than abandoning failed jobs; bounded retries continue with backoff and expired leases remain recoverable.

See the [private file ADR](../../../docs/adr/0003-private-file-content-and-cleanup.md) for the storage/transaction boundary. Migrations extend the retained M01–M09 schema; startup does not migrate automatically. The [Postman recipe](../postman/README.md) demonstrates intent, upload, finalization, attachment download and trash/restore commands.

## API operations

All paths below are relative to `/api/v1/workspaces/:workspaceId`. Authentication is required, including when a content URL contains a grant.

| Method | Path                                            | Purpose                                                         |
| ------ | ----------------------------------------------- | --------------------------------------------------------------- |
| POST   | `/files/upload-intents`                         | Reserve quota and create the originating attachment             |
| POST   | `/files/:fileId/upload-grants`                  | Refresh an upload grant before intent expiry                    |
| PUT    | `/files/:fileId/content?grant=...`              | Upload exact binary bytes                                       |
| POST   | `/files/:fileId/finalize`                       | Verify stored bytes and scan before readiness                   |
| GET    | `/files/:fileId`                                | Read authorized metadata or a retained placeholder              |
| POST   | `/files/:fileId/download-grants`                | Issue a short-lived grant for one active attachment             |
| GET    | `/files/:fileId/content?grant=...`              | Reauthorize and download verified bytes                         |
| DELETE | `/files/:fileId`                                | Trash the file and schedule retained-content cleanup            |
| POST   | `/files/:fileId/restore`                        | Restore verified retained content before purge                  |
| GET    | `/file-attachments?targetType=...&targetId=...` | List links with origin visibility applied before totals/cursors |
| POST   | `/file-attachments`                             | Link a ready file to another authorized target                  |
| DELETE | `/file-attachments/:attachmentId`               | Detach a link while retaining its identity                      |

## Invariants

- Quota reservation, initial attachment, events, audit and the idempotent response commit together under the workspace lock. A failed command reserves nothing.
- An object key, declared identity and originating attachment never change. Immutable retries acknowledge identical bytes; conflicting bytes cannot overwrite content.
- Readiness requires exact size/checksum/MIME and a clean scan. Actual integrity is checked again when serving bytes.
- Detach replay rechecks current access before returning its cached result. Detaching the last link trashes the file; restoring it can reactivate its original link.
- Cleanup claims commit a purge barrier before storage deletion. A stale worker cannot finish another worker's claim, and successful deletion releases quota only with the committed `PURGED` state.
- File/attachment placeholders and cleanup history remain retained. Storage deletion and post-deletion database failures are recoverable without assigning a new object key.

M10 contributes 15 HTTP/filesystem integration tests and 2 retained-upgrade/SQL tests. Migrations 0020–0022 were applied to the local database; live health/readiness returned 200 and the new unauthenticated attachment route returned 401.

The Postman collection has 194 requests, including 14 M10 examples covering all 12 operations; schema, scripts, variables, JSON bodies and the exact binary fixture were statically checked.
