# M01–M04 implementation and operations

This slice implements the platform/database foundation (M01), authentication (M02), reliable commands/events (M03), and workspaces/RBAC (M04). Product APIs beginning with teams/workflows (M05) remain deferred. This describes implementation guarantees; staging, load, provider and production acceptance remain gates in the [backend roadmap](../../../docs/roadmap/BACKEND_MILESTONES.md).

## HTTP contract

Business routes use `/api/v1`. Success responses use `{ data, meta: { requestId, timestamp } }`; errors use the common error envelope. UUIDs identify users/workspaces/memberships; events use ULIDs. Timestamps are UTC ISO 8601 strings. List endpoints accept bounded `limit` and opaque `cursor`; Pagination fields (`cursor`, `nextCursor`, `hasNext`, `limit`, `total`) appear directly in `meta`, with a flat `data` array. Retain `meta.nextCursor` rather than constructing cursors.

| Method               | Path after `/api/v1`                                                   | Capability                                        |
| -------------------- | ---------------------------------------------------------------------- | ------------------------------------------------- |
| POST                 | `/auth/signup`, `/auth/login`, `/auth/refresh`                         | Registration, password login, refresh rotation    |
| POST                 | `/auth/logout`, `/auth/logout-all`                                     | Revoke current/all user sessions                  |
| GET / DELETE         | `/auth/sessions`, `/auth/sessions/:id`                                 | List own sessions; revoke an owned session        |
| POST                 | `/auth/email-verification/request`, `/auth/email-verification/confirm` | Request/consume email verification                |
| POST                 | `/auth/password-recovery`, `/auth/password-reset`                      | Generic recovery request and one-time reset       |
| POST                 | `/auth/magic-link/request`, `/auth/magic-link/consume`                 | Request/consume sign-in link                      |
| GET / PATCH          | `/me`                                                                  | Read/update authenticated profile                 |
| GET                  | `/workspaces/active`                                                   | Read selected workspace                           |
| POST                 | `/workspaces/:workspaceId/leave`                                       | Leave workspace with final-owner protection       |
| GET / POST           | `/workspaces`                                                          | List workspaces; create workspace and owner       |
| GET / PATCH / DELETE | `/workspaces/:workspaceId`                                             | Read, update/archive/restore, move to trash       |
| POST                 | `/workspaces/:workspaceId/select`                                      | Select user's current workspace                   |
| GET                  | `/workspaces/:workspaceId/members`                                     | List memberships                                  |
| PATCH / DELETE       | `/workspaces/:workspaceId/members/:membershipId`                       | Change role/state; set membership to LEFT         |
| GET / POST           | `/workspaces/:workspaceId/invitations`                                 | List/issue invitations                            |
| DELETE               | `/workspaces/:workspaceId/invitations/:invitationId`                   | Revoke invitation                                 |
| POST                 | `/workspaces/invitations/accept`                                       | Accept verified-email invitation                  |
| GET / PATCH          | `/workspaces/:workspaceId/preferences`                                 | Read/update own theme/timezone                    |
| GET                  | `/workspaces/:workspaceId/outbox`                                      | Owner-only delivery failure/quarantine monitoring |

`GET /health` and `GET /health/ready` are public, version-neutral probes. Readiness fails with 503 when the bounded PostgreSQL check fails; liveness is independent of database availability. Swagger is opt-in at `/docs`.

Workspace mutations, including DELETE, require a UUID `Idempotency-Key`. Authentication/profile operations are exempt; authentication secrets are never cached as command responses. Default-deny authentication allows only explicitly public auth/probe routes without a bearer token.

## Authentication and browsers

Passwords use scrypt. Access tokens validate configured issuer/audience and HS256 algorithm. Opaque refresh and verification/recovery/magic tokens are stored as hashes. Refresh rotation persists session families; reuse revokes the family. Protected requests reload persisted session/user state, rejecting revoked sessions and disabled accounts without waiting for access-token expiry. Password reset revokes sessions. Transactional token consumption is one-time and expiry checked.

Browser requests must send an approved `Origin`. Login/signup/refresh issue `tream_refresh` cookies with HttpOnly, SameSite=Strict and `/api/v1/auth` path; production adds Secure. Cookie refresh requires the approved origin. Browser responses omit the raw refresh token. Non-browser clients can submit/receive refresh tokens explicitly. Keep access tokens in application memory; client integration is M15. Cross-site frontend/API hosting requires a deliberate cookie/CSRF contract change.

PostgreSQL-backed abuse counters are shared across replicas. Recovery/token requests use generic responses. Secrets must stay out of logs, events, audit metadata and command caches.

## RBAC and lifecycle invariants

Roles belong to workspace memberships, not global users or JWT claims. Reads/commands reload active membership and lifecycle; commands authorize before cached-result replay. A previous key cannot bypass a subsequent role downgrade/removal.

| Role   | Current scope                                                            |
| ------ | ------------------------------------------------------------------------ |
| OWNER  | Settings/lifecycle, invitations, all membership roles, outbox monitoring |
| ADMIN  | Settings/invitations; manages MEMBER/GUEST, never OWNER/ADMIN            |
| MEMBER | Workspace/member reads and own preferences; no administrative writes     |
| GUEST  | Workspace shell and own preferences; no member list/product access       |

Product permissions exist for future modules but do not mount issue/team APIs. Guests need an explicit sharing model before product access is enabled.

- Creation atomically establishes an active owner. Membership changes serialize on the workspace and preserve an active owner. ADMIN cannot self-promote or manage privileged memberships.
- Foreign identifiers do not grant access. SUSPENDED/LEFT members cannot act. Invitations expire after seven days and require the accepting user's verified matching email. The issuer must remain authorized at acceptance.
- Archive preserves identity/history; trash sets `deletedAt`. Restoring trash requires an owner within the current 30-day restoration window. Hard purge is deferred. Product writes are denied for archived/deleted workspaces.
- Workspace/membership/invitation/preference commands persist event/audit facts alongside mutation. Invitation responses never expose raw tokens or hashes.

## Transactions and delivery

`DatabaseTransaction` is the shared transaction type. `CommandBus` takes a transaction callback and optional authorization callback. Identity includes principal, method, concrete route, key and canonical request hash. PostgreSQL advisory transaction locks serialize matching commands. Changed bodies conflict; successful JSON business results persist in the same commit as mutation/events/audit. Failures roll back all effects. HTTP request metadata belongs to the current request rather than the cached business result. Results expire after 24 hours.

Event insertion validates the registered `(event_type, schema_version)` and envelope. Aggregate heads reserve one revision per aggregate/transaction, permitting several facts for one revision. Historical events retain legacy provenance rather than receiving a fabricated version 1. Consumption replay retains the original event ID instead of inserting new live facts.

`EventConsumerRegistry` registers named handlers; events queue jobs for registered consumers. Deferred notification/integration handlers are not simulated. `OutboxHost` polls enabled consumers. Claims use PostgreSQL `SKIP LOCKED`, bounded leases, retries and quarantine. Handler database effects and unique event/consumer receipts commit together, providing one committed same-database effect under retry. This does not cover arbitrary external calls. Owners inspect failed/quarantined jobs through the outbox endpoint.

Authentication and invitations share a durable mail outbox, queued in the token/invitation transaction. AES-256-GCM encrypts message payloads; successful delivery clears ciphertext. SMTP is at least once: a crash after provider acceptance and before database acknowledgement can resend. Stronger guarantees require provider-specific idempotency/reconciliation.

`BACKGROUND_WORKERS_ENABLED=false` disables polling for deterministic development/tests, which may call `dispatchReady()` explicitly. Enable polling on designated production worker replicas and monitor pending/failed mail, queue age and quarantine. Claims coordinate multiple replicas. Enabling polling neither configures SMTP nor adds consumers for deferred modules.

## Configuration and migrations

CI uses Node 24, pnpm 11 and PostgreSQL 16. `.env.example` documents local values. Production must supply non-development JWT secrets, `AUTH_MAIL_ENCRYPTION_KEY` (32 random bytes as 64 hex characters), explicit database credentials, approved HTTPS CORS/link origins and SMTP settings. Keep the encryption key stable while deliveries remain pending; rotation requires draining or explicitly re-encrypting queued payloads.

`TRUST_PROXY_HOPS` defaults to zero; configure the actual trusted topology. Pool size, connection timeout and statement timeout bound database usage. CORS accepts explicit comma-separated origins. Swagger follows deployment access policy. Background polling has a separate flag.

Use [provision-roles.sql](../scripts/provision-roles.sql) as an administrator-reviewed permission-group setup after migrations. It creates NOLOGIN runtime/migrator groups; provision login identities and grant membership separately. Existing object ownership requires an explicit operator transfer before the migrator can manage those objects. Runtime identities must never inherit migration or database-owner privileges. Run `pnpm --filter server db:migrate` explicitly with a migration role. Use a separate non-owner application role that cannot own tables, bypass history protections, truncate history or create schema objects. Maintenance/purge credentials require separate privileges and operational authorization. Do not commit passwords. Application startup does not migrate.

Retained Drizzle history is the upgrade baseline; incremental migrations implement this slice. The [84-table ERD](../../../docs/database/linear-workspace.dbml) remains the broader target. Its [SQL supplements](../../../docs/database/README.md) assume that target layout and are not interchangeable with runtime migrations. Reconcile selected entities before generating later migrations; a clean DBML export is not an upgrade script.

## Verification and remaining gates

```sh
pnpm --filter server lint
pnpm --filter server check-types
pnpm --filter server test
pnpm --filter server test:e2e
pnpm --filter server build
TEST_DATABASE_URL=postgresql://postgres:postgres@localhost:5432/tream_test pnpm --filter server test:integration
```

The [backend CI workflow](../../../.github/workflows/backend.yml) runs these checks with PostgreSQL 16. The integration suite creates a separate temporary database and applies migrations; test credentials need database creation privileges and must be separate from the application's role. Unit/mocked/bootstrap HTTP checks alone do not prove PostgreSQL behavior.

Actual SMTP provider delivery, browser integration, deployment credentials/networking, load targets, restore/PITR, staging soak and production rollout are not certified by these checks. They remain M15–M18 acceptance work. This implementation does not deploy to production.

Legacy email and workspace-slug normalization refuses ambiguous collisions before updating keys. Resolve collisions explicitly before migration; users are never silently merged. The upgrade tests verify legacy session-family backfill and preserve unverified email state.

Historical event facts keep null version metadata. Existing delivery-attempt rows retain distinct `legacy:<attempt-id>` provenance keys and remain FAILED for explicit reconciliation; live consumers never claim those keys. The upgrade does not reinterpret historical payloads as version 1 events.

## Local verification evidence

Validated against an isolated native PostgreSQL 16 instance on 2026-09-30: 184 unit/contract tests, 15 HTTP bootstrap tests, and 26 PostgreSQL integration tests passed. Integration coverage includes migration from retained schema 0006 to current, legacy identity/session/event-attempt preservation, runtime-role DDL/TRUNCATE denial, concurrent commands/ownership/worker claims, and cursor precision regressions. Server lint, typecheck and production build passed. SMTP uses a recording provider in the integration suite; hosted CI, staging, load and production deployment remain unexecuted. No developer or production database was migrated by this verification.
