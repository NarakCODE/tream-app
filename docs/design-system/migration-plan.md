Custom themes are shown as a separate final implementation increment because their reach is data-dependent rather than a countable set of static color pairs. They are a prerequisite before claiming **all-theme compliance**, even if reference-dark migration lands earlier. No finite palette table certifies arbitrary custom input.

## Rollout sequence and review boundaries

Land tokens with the necessary focus/error consumers together. Changing `destructive-foreground` without FormMessage/Alert migration would confuse semantic roles; token extraction alone is not the completed design system. Land each subsequent primitive change before converting its callers; otherwise call-site overrides can undo it.

Start representative manual coverage with login/signup/onboarding/workspaces, org sidebar/settings, issue list/details/inbox, project list/peek/timeline, cycles/charts, command palette and create-issue dialog. Then enumerate all retained theme presets and every changed route closure from the inventory. Capture screenshots for desktop/narrow widths, keyboard focus and error/loading states. Keep browser-unavailable or inaccessible routes explicitly unverified.

For each increment, run relevant package lint/type checks via Turbo according to current scripts and add tests only where a behavior change warrants them under repository guidance. This task did not change app behavior or run those checks. Re-run the inventory and compare exact competing value locations; fewer raw values alone does not prove better semantics.

## Rollback and acceptance

Each increment should have a focused commit or PR preserving pre-existing dirty work. Keep theme preference keys and user data compatible. If theme readability or overlay reachability regresses, revert the affected increment while retaining the documentation/evidence. Do not remove other themes as a shortcut: D1 explicitly retains them.

Migration is complete when tokens/docs match, scoped lint rejects new appearance violations, all applicable component states have evidence, all retained fixed themes pass their pair matrix, and custom theme validation enforces the same thresholds. No app screen is declared verified by this source audit alone.
